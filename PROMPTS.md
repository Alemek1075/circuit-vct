# Етапи по одному вікну до п'яти годин

Кожен етап починається з перевірки стану репозиторію й завершується робочою збіркою, тестом та записом фактичного результату в `PROGRESS.md`. Код і документація кожного завершеного етапу відправляються до GitHub. Не позначати наступний етап виконаним за самим планом.

## Етап 1. Дані й основа, до 4 годин

Створити новий ASP.NET Core MVC .NET 8 проєкт із EF Core SQLite. Моделі `Tournament`, `Team`, `Match` і migrations. Ввести два турніри: завершений Paris 2025 з 14 перевіреними результатами та Shanghai 2026 з 16 учасниками й оголошеними першими матчами без рахунків. Додати джерела з датою знімка. Перевірити збірку, міграцію та відсутність вигаданих результатів.

## Етап 2. Публічна сітка, до 5 годин

За `DESIGN.md` зробити адаптивний огляд турніру, верхню й нижню сітку, зв'язки між матчами, таблицю місць і картки матчів. Вибір турніру, команди й матчу мають бути дієвими. При виборі команди підсвітити її повний шлях. Перевірити обидва турніри в браузері на широкій і мобільній ширині, клавіатуру та відсутність переповнення сторінки.

## Етап 3. Керування й API, до 5 годин

Реалізувати MVC CRUD для турнірів, команд і матчів із серверною валідацією, явним збереженням UTC та захистом форм від CSRF. Додати JSON CRUD API, `skip/limit/nextLink` для матчів і коректні HTTP стани. Не допускати зміни історичних результатів без явної дії редактора. Додати API сценарії й перевірити створення, зміну, видалення та помилки.

## Етап 4. Подання команд і матчів, до 4 годин

Окремі адреси команди й матчу з усіма зв'язаними іграми, зрозумілими переходами та технічними SEO метаданими. На сторінці матчу показувати лише перевірену інформацію; для майбутніх ігор залишати порожній рахунок. Додати пошук команди й фільтри розкладу, перевірити порожні стани.

## Етап 5. Живе оновлення й статистика, до 5 годин

Додати SignalR для зміни рахунку без перезавантаження та малі графіки зі статистики матчів. Провести відтворюване порівняння WebSockets, SSE і Long Polling за однакового сценарію. Живі дані дозволені лише від власного редактора; не називати це офіційною трансляцією VCT.

## Етап 6. Поставка й якість, до 4 годин

Додати Dockerfile, Compose з постійною SQLite базою, health endpoint, браузерні наскрізні тести й GitHub Actions. Окремо перевірити запуск контейнера та CI. Записати точні результати, а недоступний Docker чи зовнішній сервіс не називати успіхом.

## Етап 7. Доступ і публікація, до 5 годин

Захистити запис OAuth2 провайдером, перевірити відмову гостю та сценарій входу. Лише після цього розгорнути застосунок із постійним сховищем і секретами поза Git, налаштувати CD з `main`, перевірити публічний реліз і провести зовнішній SEO аудит. Якщо немає облікових даних або доступу до хмари, зафіксувати точну межу без удаваного деплою.
